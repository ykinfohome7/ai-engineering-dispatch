# Експлоатация, старт и възстановяване — BGDB AI-EMDS

> 🇧🇬 Българска версия на [основните инструкции](../OPERATIONS.md).

## Работа в GitHub Codespaces

> 🇧🇬 Използвайте частен port forwarding за Paperclip.

1. Стартирайте Codespace от `main` (Node 24.11+, pnpm 9.15.4, Python 3.12).
2. Пуснете `bash scripts/bootstrap.sh` за тестове на Python помощника.
3. Използвайте `PYTHONPATH=src python3 -m bgdb_dispatch.cli roles` за списък с наличните роли.
4. Стартирайте `bash dispatcher/install.sh` или `bash scripts/start-paperclip.sh` — Paperclip обичайно използва порт 3100.
5. Регистрирайте реалните агенти, задайте бюджет и човешки одобрения; не ги приемайте за автоматично настроени.
6. Проверете връзката с `PYTHONPATH=src python3 -m bgdb_dispatch.cli doctor`.
7. Без `--execute` подаването на задача е само тестова подготовка.

## KSSH и Tailscale

> 🇧🇬 След всяко възстановяване на Codespace проверете реалния статус на връзките.

Проверете Tailscale и KSSH чрез `tailscale_status` и `server_test`. Връзката се губи, ако Codespace бъде спрян, а `postStartCommand` се изпълнява едва след ново стартиране. Постоянен шлюз изисква работещ Proxmox хост. Използвайте `run_command` само след преглед на точната команда; файлови записи чрез SFTP изискват одобрение.

## PostgreSQL и архивиране

> 🇧🇬 Примерната външна база е за втория етап и няма публичен порт.

Създайте локален игнориран `.env` със силна парола за PostgreSQL и изпълнете от корена на проекта `docker compose --env-file .env -f infra/postgres/docker-compose.yml up -d` само в одобрена среда. За архив задайте абсолютен `BACKUP_DIR` извън Git и стартирайте `bash infra/postgres/backup.sh`. За ежедневно изпълнение е нужен отделен cron/systemd timer; самият скрипт не го инсталира. Пазят се 14 дни. Проверете възстановяването регулярно.

## Proxmox LXC пример

> 🇧🇬 Скриптът е dry-run по подразбиране; не инсталира Paperclip автоматично.

`infra/proxmox/create-lxc.sh` изисква път към одобрен Debian 12 шаблон, свободни CTID, storage, bridge и SSH публичен ключ. Той показва командите, без да създава контейнери. Реалното изпълнение изисква `--apply` и `BGDB_HUMAN_APPROVED=YES` след отделно човешко одобрение. Използвайте само върху упълномощен Proxmox сървър и проверете настройките за защитна стена.

## Мониторинг и седмичен отчет

> 🇧🇬 Следи отворените Issues, Pull Requests, разходи и одобрения.

Пуснете `bash scripts/agent-report.sh` след удостоверяване на GitHub CLI (`gh`). Сравнете резултатите с Paperclip задачи, CI, бюджети, логове, Tailscale статус и резервни копия. Примерната документация не изпраща автоматични аларми.

## Безопасност

> 🇧🇬 Не изпълнявайте опасни операции по SSH без разрешение и план за връщане.

Запазвайте данните само в одобрени системи и не споделяйте токени или частни ключове в Git. Използвайте [стандартите за сигурност](SECURITY-STANDARDS.md), [инвентара](INVENTORY.md) и [пътната карта](../../ROADMAP.md).
