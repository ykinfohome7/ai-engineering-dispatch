# Архитектура на BGDB AI-EMDS

> 🇧🇬 Пълен български преглед на [основната архитектура](../ARCHITECTURE.md).

## Логически поток

> 🇧🇬 GitHub Issue ↔ Paperclip засега се свързват ръчно; схемата е целево състояние.

```text
Потребител
    |
    v
ChatGPT (приемане/план)
    |
    v
GitHub Issue -- ръчно свързване --> Paperclip (диспечер)
    |                                      |      |      |
    |                                PostgreSQL бюджети одобрения
    |                                      |
    |                    +-----------------+--------------------+
    |                    |          |           |         |       |
    |                Architect  Developer  Developer  Reviewer  QA/Docs
    |                            Claude     Codex
    +----------------------------+-----------+---------+
                                 |
                         feat/<issue>-name
                                 |
                              GitHub PR
                                 |
                         Независим review + CI
                                 |
                            Одобрено merge
                                 |
                                DevOps
                                 |
                                KSSH
                                 |
                         Tailscale / ACL
                                 |
                     Одобрени сървъри / Proxmox
```

## Компоненти и отговорности

> 🇧🇬 Всеки слой има конкретна задача и отделни права.

- **ChatGPT:** приема задачи и формулира критерии за приемане.
- **GitHub:** следи всяка задача с Issue; управлява клони, PR и CI.
- **Python intake:** създава локален план и по избор Paperclip задача; не е отделна система за автоматично управление на агенти.
- **Paperclip:** регистър на агенти, диспечиране, ресурси, лимити, одобрения и данни във вграден PostgreSQL (етап 1).
- **Агенти:** Architect, Claude Code Developer, Codex Developer 2, Reviewer, QA, DevOps и Docs.
- **KSSH:** само одобрен SSH/MCP достъп до сървърите.
- **Tailscale:** частна мрежа и ACL правила.
- **Proxmox:** постоянно работеща инфраструктура и възстановяване.

## Етап 1: Codespaces

> 🇧🇬 Начален тестов режим без гарантирана непрекъсната работа.

Node.js 24.11+, pnpm 9.15.4, Paperclip Git submodule и вграден PostgreSQL. Порт 3100 трябва да е Private. При спиране на Codespace спират и неговите услуги, включително KSSH/Tailscale, ако се намират там.

## Етап 2: Proxmox

> 🇧🇬 Постоянно работещ VM/LXC с архиви, логове и сигурна мрежа.

Планирайте постоянен диск, systemd, отделна база PostgreSQL при нужда, архивиране и пробно възстановяване, централизирани логове, мониторинг, лимити на ресурсите, TLS и Tailscale. Не включвайте публичен Funnel за административни услуги без изрично одобрение и защита.

## Неприключени интеграции

> 🇧🇬 Документирана архитектура не е равнозначна на готово внедряване.

Няма потвърдена автоматична синхронизация GitHub ↔ Paperclip, регистрирани и тествани агенти, лимити на бюджетите, approval gates, постоянна KSSH/Tailscale връзка или Proxmox deployment. Гарантираното изискване за независим review трябва да се активира чрез GitHub branch protection/rulesets.

Вижте [Инвентар](../INVENTORY.md), [Операции](../OPERATIONS.md) и [Правила за агенти](AGENTS.md).
