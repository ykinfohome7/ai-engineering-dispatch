# Правила за AI агентите на BGDB AI-EMDS

> 🇧🇬 Българска версия на [AGENTS.md](../../AGENTS.md).

## Седем специализирани роли

> 🇧🇬 Всеки агент има отделна отговорност и разходен бюджет.

| Агент | Отговорност | Резултат |
| --- | --- | --- |
| Architect | Изисквания, дизайн, разделяне на задачи | План, архитектурно решение |
| Developer (Claude Code) | Основна реализация | Код и Pull Request |
| Developer 2 (Codex) | Независима реализация или алтернативно решение | Код и Pull Request |
| Reviewer | Независим преглед на код и сигурност | Коментари и одобрение |
| QA | Автоматични/ръчни проверки | Тестове и доказателства |
| DevOps | CI, сървъри, настройване и внедряване | План за внедряване и rollback |
| Docs | Документация и инструкции | Проверени ръководства |

## Задължителни правила

> 🇧🇬 Задача без Issue, директен push в main или самостоятелен review са недопустими.

1. **Всяка задача започва с GitHub Issue** с обхват и критерии за приемане. Свързването с Paperclip засега е ръчно.
2. Работете в отделен клон `feat/<issue>-name` или `fix/<issue>-name`; всички промени минават през Pull Request. Няма директен push в `main`.
3. Кодът се преглежда от **друг агент**, различен от автора. Трябват преминали CI тестове и изискваното човешко одобрение.
4. Изтриване, презапис, промяна на ключове и пароли, DNS, мрежово публикуване, миграции и продукционни операции изискват **изрично човешко одобрение** плюс план за връщане.
5. На всеки активен агент се задава **индивидуален лимит на токени и разходи** с предупреждения и спиране при достигане на лимита.
6. Не допускайте секретни ключове, пароли, токени, лични данни или частни сертификати в Git, Issue, PR, логове и промптове.
7. Предпочитайте диагностика с права само за четене; KSSH се ползва единствено за разрешени сървъри през Tailscale.
8. Обновявайте Paperclip чрез фиксирана версия, PR, независим преглед и тестове — никога чрез автоматично merge без преглед.

## Работен процес

> 🇧🇬 От заявката до провереното внедряване.

`GitHub Issue → Architect → Claude Code/Codex → независим Reviewer → QA → Docs → CI → одобрено сливане → DevOps`.

## Състояние и ограничения

> 🇧🇬 Правилата в Git не активират автоматично реални акаунти или защити.

Предстои регистриране на реалните агенти в Paperclip и индивидуалните бюджети, потвърждаване на approval gates, настройване на GitHub rulesets, интеграция GitHub Issue ↔ Paperclip и постоянна инсталация на Proxmox. Вижте [Инвентара](../INVENTORY.md).
